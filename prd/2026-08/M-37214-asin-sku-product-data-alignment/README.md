## 业务背景和价值

AI 商品视频已迁移为 ERP 内的 Java 独立菜单模块。新建任务第一步“商品资料”支持“店铺 + ASIN”和“系统 SKU”两种来源，但取数逻辑需要分别与运营生图、美工生图的现行能力保持一致。

本期目标是让相同业务输入在 AI 视频与对应 AI 生图系统中取得相同的商品对象和资料结果，并通过共享内部取数能力减少重复开发和后续多处维护。

## 需求概述

- 店铺 + ASIN：完整采用运营生图 M-37095 中的单条商品资料取数及其后续完整取数链路。
- 系统 SKU：完整采用美工生图 M-37150 中的单条 SKU 商品图文信息和白底图链路。
- 只改造 ERP“AI视频 > 任务管理 > 新建任务”第一步“商品资料”的查询与回填。
- 保留现有来源选择、字段、按钮、布局和提示文案；不新增批量创建任务，不需要 HTML 原型。
- 不调整 Prompt 消息结构、任务生成流程和历史任务数据。

## 功能需求

### 1. 两种来源的统一规则

| AI 视频来源 | 统一目标 | AI 视频关键边界 |
|---|---|---|
| 店铺 + ASIN | 与 M-37095 及完整取数链路保持一致，包括 Listing 硬排除、逐级择优、五点描述、尺寸和白底图 | 有效结果必须取得同一最终 Listing 对象内的 MSKU 和系统 SKU；标题、类目也从该对象读取。MSKU 用于查询五点描述，系统 SKU 用于查询尺寸和白底图 |
| 系统 SKU | 与 M-37150 保持一致，包括唯一产品对象判断、商品图文字段和白底图 | SKU 去除首尾空白后按完整字符串查询；必须取得当前 SKU 的唯一产品对象，不按状态字段过滤，不使用 Listing 或其他数据源兜底 |

两种来源相互隔离，不跨来源补齐或拼接资料。所有返回结果按 `sourceId + asin`、`sourceId + msku` 或 `sku` 等稳定业务键关联，不按数组位置关联。

### 2. 关键结果和异常边界

- 店铺 + ASIN 无有效同对象 `msku + sku` 时查询失败；取得有效对象后，五点描述、尺寸或图片失败不抹掉已经取得的其他资料。
- 店铺 + ASIN 使用接口返回的全部有效五点描述；任一尺寸无效时整套尺寸留空。
- 系统 SKU 无产品、返回多个同 SKU 产品对象、业务失败或响应结构异常时查询失败；取得唯一对象但部分字段为空时，回填有效字段并允许人工完善。
- 系统 SKU 的部分尺寸有效时只回填有效单项，尺寸整体仍视为不完整；具体字段映射与 M-37150 一致。
- 两种来源均只自动取得对应系统 SKU 的白底图，按稳定键关联、保持返回顺序、清理空值并按 URL 去重后取前 5 张。自动图与人工上传图片合计须为 1～5 张。
- 主资料有效但字段或图片不完整时，用户可以按现有页面能力人工补齐。进入生成总分镜脚本前，须具备有效标题、类目、三项大于 0 的有效尺寸、至少一条有效五点描述或卖点、1～5 张参考图，并满足 AI 视频现有其他校验。
- 不增加其他上游取数接口、数据库直查、跨来源兜底、自动重试或历史缓存作为失败替代方案。

### 3. 查询覆盖和资料失效

- 查询结果须绑定准确查询条件：店铺 + ASIN 使用当前授权店铺 `sourceId + ASIN`，系统 SKU 使用去除首尾空白后的完整 SKU。
- 店铺 + ASIN 取得同一最终 Listing 对象内的有效 `msku + sku`，或系统 SKU 取得当前 SKU 的唯一产品对象，即主查询成功；五点描述、尺寸或图片缺失、失败属于补充资料不完整，不把主查询改判为失败。
- 完全相同查询条件再次查询时，主查询成功则本次结果整体覆盖原商品资料、自动图和人工上传图，本次缺失的补充资料保持为空，不沿用上一次内容；只有主查询失败时才保留原资料。
- 来源、店铺、ASIN 或系统 SKU 发生变化时，旧查询结果和人工修改内容立即失效并清除。新条件未查询或查询失败时保持为空，不恢复旧资料。
- 当前查询条件与商品资料绑定条件不一致时，不能进入生成总分镜脚本。

### 4. 共享内部取数接口建议

1. 建议研发优先将两条现行取数链路复用或封装为 ERP 内部共享自用接口，由运营生图、美工生图和 AI 视频共同调用，避免三套系统分别实现和维护相同规则。
2. “店铺 + ASIN”与“系统 SKU”应保留输入、返回和异常含义明确的两套调用能力，不合并为大量字段可空、来源含义模糊的通用接口。
3. 如当前已有共享服务则直接复用；不适合新增网络接口时，可以采用共享领域服务或公共组件。具体服务归属、接口路径、类名、表名和数据结构由研发结合现行 Java 架构设计。
4. 查询条件变化后的页面清理、人工修改、任务保存和 Prompt 组装仍由各业务模块负责，不放入共享取数能力。
5. 研发实施前须检查当前 Java 的实际调用、权限、回填和保存链路。如现网实现或真实接口与上述正式基线冲突，先反馈产品确认，不得自行选择旧逻辑或增加兜底。

### 5. 数据保存和历史兼容

- 查询结果只作为页面初始值；生成总分镜脚本和保存任务时使用页面当前最终确认值，现有 Prompt 结构和调用顺序不变。
- 店铺 + ASIN 保存来源、店铺上下文、ASIN、最终 MSKU、系统 SKU 和最终商品资料；系统 SKU 保存来源、输入 SKU 和最终商品资料。具体技术字段由研发设计。
- 本需求只影响上线后的新查询，不回查、回刷或修改历史任务。
- 历史任务编辑或重新生成时继续使用任务已经保存的商品资料。

## 不在本期范围

- 页面交互、字段、文案或布局调整；
- 批量创建任务，以及 AI 生图的批量规则、“待完善／待提交”任务状态、固定商品文本拼接和 2500 字规则；
- Prompt、模型和视频生成链路调整；
- 上游接口改造、历史数据回刷或新增兜底数据源。

## 风险描述

| 风险 | 控制要求 |
|---|---|
| 三个系统分别复制取数规则，后续容易产生差异 | 优先复用或抽取共享内部能力；使用同一固定数据验证业务结果一致 |
| 两种资料来源或多个返回对象发生串用 | 两条来源独立处理，按稳定业务键关联；ASIN 结果字段来自同一最终 Listing 对象 |
| 修改查询条件后仍保留旧资料 | 查询结果绑定准确条件；来源、店铺、ASIN 或 SKU 变化后立即清除旧资料 |
| 当前 Java 实现与参考资料可能存在差异 | 实施前核对真实代码和接口，存在冲突时先由产品确认 |

## 验收标准

| # | 验收场景 | 预期结果 |
|---|---|---|
| 1 | 打开 AI 视频新建任务第一步并切换两种来源 | 页面字段、按钮、布局和文案保持现状，无批量入口或新交互 |
| 2 | 使用同一固定 Listing 数据对比 AI 视频与运营生图 | 硬排除、择优顺序、最终 Listing、MSKU、SKU、标题、类目、五点描述、尺寸和白底图结果一致 |
| 3 | ASIN 第一候选缺少 MSKU 或 SKU，后续候选两者有效 | 降级选择后续有效候选，相关字段均来自同一最终 Listing 对象；全部候选无有效同对象结果时查询失败 |
| 4 | 使用同一固定 SKU 数据对比 AI 视频与美工生图 | 唯一产品对象判断、标题、类目、尺寸、卖点和白底图结果一致，不按状态字段过滤或使用其他数据源兜底 |
| 5 | 补充字段或图片缺失、失败 | 主资料有效时回填本次已有内容并允许人工完善；ASIN 与系统 SKU 的尺寸不完整处理分别符合对应基线；标题、类目、三项大于 0 的有效尺寸、至少一条五点描述或卖点、1～5 张参考图及现有其他校验全部满足后才能继续 |
| 6 | 相同条件下分别发生主查询成功但补充资料缺失、主查询失败 | 主查询成功时整体使用本次结果，缺失项保持为空，不沿用上次文本或图片；主查询失败时保留原资料 |
| 7 | 修改来源、店铺、ASIN 或系统 SKU | 旧回填资料、人工修改和图片立即清除；新条件成功前不能进入下一步，不恢复或混用旧资料 |
| 8 | 人工完善资料后生成总分镜脚本 | 使用页面当前最终商品资料，现有 Prompt 结构和调用顺序不变 |
| 9 | 检查历史任务和上线后新查询 | 历史任务不回查、不回刷，继续使用已保存资料；新查询执行本需求规则 |
| 10 | 使用不同权限账号及返回顺序变化的数据查询 | 继续受 ERP 现有权限约束；结果按稳定业务键关联，不发生跨账号、跨店铺或跨对象串用 |
